# 🔧 技术规范：我的专属偶像生成器

> 本文档是代码的「施工图纸」：怎么实现、数据什么格式、怎么验证，以这里为准。
> 改代码之前必须先读本文档。

## 1. 核心原则

1. **零构建、零外部依赖**：纯 HTML + CSS + 原生 JavaScript，不用任何框架、构建工具、CDN、网络资源。断网也能玩。
2. **双击即玩**：`index.html` 双击直接用浏览器打开，全程不涉及本地服务器。
3. **数据与逻辑分离**：偶像数据只在 `data.js`；游戏逻辑只在 `app.js`。
4. **纯数学落点**：转盘结果不靠读取 DOM 判断，而是由旋转角度纯数学计算，结果必然与画面一致。
5. **兼容性**：只使用现代浏览器（Chrome / Safari / Edge）普遍支持的特性。

## 2. 四个文件职责

| 文件 | 职责 | 改动规则 |
| --- | --- | --- |
| `index.html` | 页面骨架：标题、步骤指示器、属性栏、转盘区、结果弹层；按 data.js → app.js 顺序加载脚本 | 改结构时动它 |
| `style.css` | 全部样式与动效（梦幻柔彩主题） | 改外观时动它 |
| `data.js` | 全部数据：等级映射、属性表、称号表、评级表、调色板、组合与成员数据 | **加组合 / 改分数只许动它** |
| `app.js` | 全部逻辑：状态机、转盘渲染与旋转、落点计算、填格、总评、弹层 | 改玩法逻辑时动它 |

### 3.4 数据硬性约束（加数据必须满足）

- ❌ 不允许出现 **D** 等级
- ❌ 每位成员 8 项里 **C+/C 合计最多 1 项**
- ✅ 每位成员 8 项属性必须**齐全**（键与 ATTRS id 一致）
- ✅ 组合 id、成员 id 全局唯一
- 验证命令（语法检查）：`node --check data.js`

### 3.5 其他数据表

- `ATTR_TITLES`：最高属性 id → 趣味称号（dance→主舞级配置 等）
- `RATING_TABLE`：`[最低平均分, 评级名]` 数组，从高到低排列，最后一项 `[0, '热血出道']`
- `WHEEL_PALETTE`：10 个柔彩色，组合盘/属性盘循环取用
- `RESULT_COMMENTS`：结果小评语池，键 = `RATING_TABLE` 的评级名（共 8 档），每档含两组：`gap`（有强弱差时用，模板带 `{top}` 最强属性 / `{weak}` 最弱属性占位符，≥3 条）与 `even`（无强弱差/六边形时用，无占位符，≥1 条）；由 app.js 的 `pickComment(评级, 最强属性名, 最弱属性名)` 按有无强弱差选组、替换占位符后返回；最强/最弱属性由 `calcOverall()` 返回（并列取先出现的一格）

## 4. 转盘实现（app.js）

### 4.1 渲染

- 扇区用 CSS `conic-gradient(from -90deg, ...)`：从 12 点方向开始顺时针排布
- 相邻扇区间插入 1° 白色细线（n ≥ 15 时为 0.6°）
- 文字标签：每个标签 = 一个 `inset:0` 全层旋转容器（`rotate(扇区中心角)`）+ 内部竖排 span；span 用 `writing-mode: vertical-rl` 竖排，**显式设置宽（= 字号，一个字形列）与高（= 文字列长度含字距）**，再 `translateY(-R)` 推到扇区中心线。显式定尺寸是为了绕开竖排文字在绝对定位/弹性布局下自适应尺寸的浏览器差异（曾导致标签偏离扇区中心、压到分割线）
- 标签径向位置 `R = (HUB_RADIUS + radius) / 2`；字号按扇区数分档（≤6:16 / ≤9:14 / ≤12:12 / ≤16:10.5 / 其余 9.5px），再按最长标签长度缩放到径向放得下
- 每换一盘重新渲染，角度归零

### 4.2 落点计算（纯数学，核心公式）

- 指针固定在转盘**顶部**，扇区 0 从 12 点方向顺时针开始
- 转盘旋转角度 θ（CSS `transform: rotate(θ)`）时，指针所指的「本地角度」：
  **p ≡ (360 − θ) mod 360**
- 指针所在扇区序号：`floor(p / (360 / n))`
- 转动时：
  1. 随机选目标扇区 idx
  2. 目标落点取扇区中间带：`pTarget = (idx + 0.5) * seg + (rand*0.7 − 0.35) * seg`（避开边界白线）
  3. 换算目标 θ，再从当前角度出发**加 5~7 个整圈**，保证动画时长足够

### 4.3 动画参数

- 时长：`SPIN_DURATION = 4200ms`
- 缓动：`cubic-bezier(0.17, 0.67, 0.12, 0.99)`（先快后慢的"轮盘"手感）
- 结束回调**双保险**：`transitionend`（once）+ `setTimeout(SPIN_DURATION + 400)` 兜底；`onSpinEnd` 用 `isSpinning` 标志保证幂等，只执行一次
- 中心装饰圆半径 `HUB_RADIUS = 26`（标签与渐变都要避开）

## 5. 游戏状态机

全局 `state` 对象字段：

```
slots[8]        每格数据 { groupName, generation, memberName, attrId, attrName, grade, memberId, groupId } | null
currentSlot     当前待填格 0..7
step            'attr' | 'group' | 'member'
pickedAttr / pickedGroup     本格已抽中的属性 / 组合（成员落地即填格，无需存）
isSpinning      转盘是否在转（防连点 + 幂等）
totalRotation   累计旋转角度
finished        8 格是否填满
endTimer / resultTimer / toastTimer / shareMsgTimer   定时器引用（重开时必须 clearTimeout）
shared          是否正展示朋友分享的结果卡（resetGame 清除）
```

流程：

```
空闲 → 转属性(step=attr) → 转组合(step=group) → 转成员(step=member)
     → fillSlot 填格 → 下一格回到 attr … 第 8 格填满 → finished
     → 700ms 后 showResult 弹偶像卡 → resetGame 重开
特例：进入新格时若未抽取属性只剩 1 项（即最后一格），自动选定该属性直接进入组合盘，
     不渲染/转动单扇区属性盘
```

⚠️ 已知坑：`resultTimer`（700ms 弹结果）、`toastTimer`（落定提示 1.7s 淡出）、`shareMsgTimer`（分享反馈 1.5s）在 `resetGame` 时必须 `clearTimeout`，否则旧定时器会在新一局里错误触发（已修复，改动时注意保持）。

### 5.1 分享与保存图片

- 分享链接格式：`#r=<encodeURIComponent(attrId~grade~memberId~groupId|…×8)>`；grade 显式存储，数据日后改动不影响已分享结果
- `applySharedResult()`：`init()` 末尾调用；解析并校验（8 段齐全、id 真实存在、等级合法、属性不重复），通过则填 slots + `finished` + `shared` 并直接 `showResult()`（头部显示「朋友分享的偶像卡」）；非法一律忽略按普通开局
- 分享：`navigator.share` 系统面板（不支持时降级复制链接）；小红书 = `copyText(摘要文案+链接)`；剪贴板失败回退 `document.execCommand('copy')`（兼容 file://）
- 图片：`buildResultImage(withQr)` 原生 Canvas 自绘结果卡（零依赖、2x 缩放、3:4 竖版 540×720 → 1080×1440）；`withQr=true` 底部印网址与二维码，`withQr=false` 为纯净版仅留一行站名（小红书规避站外导流审核）；**二维码以 base64 内嵌于 data.js（`QR_DATA_URL`，`loadQrImage()` 加载失败跳过不影响出图）——不用文件加载是因为 Safari 在 file:// 下把本地图片画上画布会触发「画布污染」，导致 toBlob 抛 SecurityError**；运行时零外部依赖；iOS 走 `navigator.canShare({files})` 分享面板「存储图像」入相册；**用户取消分享面板（AbortError）静默返回不算失败，分享报错自动回退 `<a download>` 直接下载**
- `resetGame` 时清 `shared` 并用 `history.replaceState` 清 hash（try/catch 包裹）

## 6. 新增组合的操作方法

1. 只改 `data.js`：在 `GROUPS` 数组末尾，照着已有组合的格式追加一个对象
2. 填写 `id`（唯一小写英文）、`name`、`generation`、`colors`（2 个颜色）、`members`
3. 每位成员 8 项属性齐全，遵守 3.4 节硬性约束
4. 验证：
   ```bash
   node --check data.js          # 语法
   # 再跑数据校验（每成员 8 项齐全、无 D、C+/C 至多 1 项、id 唯一）
   ```
5. 浏览器打开 `index.html`，转几轮确认新组合正常出现在组合盘上

## 7. 验证方式

每次改代码后必须跑「验证三件套」（详见开发流程.md）：

1. **语法检查**：`node --check app.js && node --check data.js`
2. **逻辑测试**：Node + DOM 桩（模拟 document/window/requestAnimationFrame，把 data.js + app.js 在同一个作用域里 eval 后跑断言）：落点公式角度用例（含单扇区数学边界）、标签渲染、完整模拟 3 局、末格自动填入、评语池校验
3. **浏览器实测**：`open index.html` 人工玩一局，检查转盘、填格、结果弹层、再来一局

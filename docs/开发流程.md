# 🚀 开发流程

> 本文档是「怎么干活」的标准：节奏、循环、验证、提交、回滚，照此执行。

## 1. 小步推进原则（最重要）

- **一次只做一个小步骤**：一个功能点、一个数据补充、一个样式修正——做完立即验证、提交，再开始下一步
- 禁止一口气改多处、多文件、多功能，出了问题难定位
- 每个小步骤完成后，git 提交一次，随时可以回滚

## 2. 标准开发循环

每次开发工作按以下 6 步循环：

1. **开场**：读开发日志文件夹中日期最新的一篇日志 + `docs/路线图.md`，确认待办事项，明确本步做什么
2. **改代码**：只改实现本步必需的最小范围（改前先读 `docs/技术规范.md` 或 `docs/设计规范.md` 对应章节）
3. **验证**：跑「验证三件套」（见下）
4. **浏览器实测**：`open index.html` 人工确认效果
5. **记录**：更新当天开发日志（完成事项 / 待办事项）
6. **提交**：git 提交本次改动

## 3. 验证三件套（缺一不可）

1. **语法检查**
   ```bash
   node --check app.js && node --check data.js
   ```
2. **逻辑测试**：Node + DOM 桩测试（把 data.js + app.js 在同一作用域 eval 后跑断言）——覆盖：落点公式、完整模拟对局、重抽隔离、边界情况。全部通过才继续。
3. **浏览器实测**：`open index.html`，人工玩一局确认无异常。

## 4. git 提交规范

- **时机**：每个完成的小步骤提交一次（用户不懂 git，全部 git 操作由 Claude 代劳）
- **信息格式**：`[类型] 简述`
  - `feat` 新功能 / `fix` 修 bug / `docs` 文档 / `chore` 杂项（配置、日志等）
  - 例：`[feat] 结果卡增加出道评级展示`、`[fix] 修复重抽后步骤指示器错乱`、`[docs] 更新路线图`
- 提交前用 `git status` 确认没有误纳入的临时文件

## 5. 出问题时的回滚方法

1. **查看现状**：`git status`、`git log --oneline`
2. **没提交的改动不要了**：`git checkout -- <文件名>`（还原单个文件）
3. **已提交但想退回上一个版本**：`git revert HEAD`（安全，保留历史）
4. **整个仓库回到某次提交**：`git reset --hard <提交号>`（⚠️ 会丢弃之后的提交，仅在确认不要时使用）

## 6. 开发日志规则

- 位置：`开发日志/` 文件夹，文件名 = 当天日期，如 `2026-09-12.md`
- **开场**：读日期最新的一篇日志，确认「待办事项」再动手
- **收尾**：更新当天日志——「完成事项」列清今天做完了什么；「待办事项」写下还没做完的
- 当天没有日志文件时，复制 `开发日志/_模板.md` 新建一篇
